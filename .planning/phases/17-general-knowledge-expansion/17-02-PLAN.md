# Plan 17-02: 一般知識庫離峰批次生成管線與斷點續跑

## 1. 目標
在 `src/batch/runner.py` 與 `scripts/run_nightly_batch.py` 中擴充批次生成調度能力，支援 `--general-only` 與 `--skip-general` 旗標；強化斷點續跑機制，針對已有合格答案（或未標記 `needs_regeneration`）的問答題安全跳過，避免浪費模型資源；寫入時嚴格維持 Fail-Closed 審核隔離（`review_status='pending'`）。

## 2. 實作任務
1. 擴充 `src/batch/runner.py`:
   - `BatchConfig` 新增 `general_only: bool = False`、`skip_general: bool = False`。
   - `BatchSummary` 新增 `general_generated_count: int = 0`、`general_skipped_count: int = 0`。
   - 批次生成流程：
     - 若 `general_only=True`，略過 SOAP 提煉（`enable_soap_distill=False`）與 PageIndex 樹重建（步驟 3）。
     - 選取待生成主題時，若 `general_only=True`，僅挑選 `category='general'` 之主題；若 `skip_general=True`，則過濾排除 `category='general'`。
     - 斷點續跑檢查：比對現有 `faq_cache` 中同 `(clinic_id IS NULL, topic_key, question)` 之列，若已存在且 `needs_regeneration=0`，則計入跳過數，不呼叫 LLM 重複生成。
2. 擴充 `scripts/run_nightly_batch.py`:
   - 新增 CLI 參數 `--general-only` 與 `--skip-general`。
   - 與既有 `--soap-only`、`--skip-soap` 建立互斥規則防護（如 `--general-only` 與 `--soap-only` 互斥，兩者並存報錯）。
3. 撰寫單元測試 `tests/test_nightly_general_batch.py`:
   - 驗證 `--general-only` 僅生成 general 主題，不跑 SOAP 提煉與樹重建。
   - 驗證 `--skip-general` 排除 general 主題。
   - 驗證互斥參數拋出錯誤退出。
   - 驗證斷點續跑（已存在的未標記項目自動跳過）。

## 3. 驗收標準
- `pytest tests/test_nightly_general_batch.py` 4/4 PASS。
- 批次摘要日誌正確記錄 `general_generated_count` 與 `general_skipped_count`。
