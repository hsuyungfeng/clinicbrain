  <files>src/visual/autodraft.py, tests/test_visual_autodraft.py</files>
  <behavior>
    - `normalize_tree_topic_key(doc_id: str) -> str`：將 `doc_id` 轉為小寫英數連字號格式並加上 `tree-` 前綴（若已為 `tree-` 開頭不重複加），長度夾限於 3..64，符合 `^[a-z0-9-]{3,64}$`；不合法則拋 `ValueError("schema_error")`。
    - `fetch_eligible_trees(conn, *, tree_id=None, doc_id=None, clinic_id=None) -> list[dict]`：
      * 必須套用 `visible_tree_sql(conn)` 條件，確保只讀取對外可見（已核准）之推理樹。
      * 若指定 `tree_id` 或 `doc_id` 但該樹為 `pending` 或 `rejected`，回傳空清單（呼叫端據此回傳 `"tree_not_approved"` 或 `"tree_not_found"`）。
    - `build_tree_visual_prompt(tree: dict) -> str`：
      * 組裝推理樹之 `title`（若無則用 `doc_id`）、`summary_text`、`pre_op`、`procedure`、`post_op_short`、`maintenance`。
      * 明確指示：僅說明「原理與手術／處置過程」，禁止出現具體價格、用藥劑量、百分比、任何阿拉伯數字、以及 `VISUAL_EXTRA_FORBIDDEN` 所有禁用詞（動態由 `ir.VISUAL_EXTRA_FORBIDDEN` 組入）。
      * 要求模型輸出單一 JSON 物件，結構固定為：
        - `"title"`: 1..30 字主題標題（不含數字）
        - `"keywords"`: 2..6 個關鍵字（每個 2..12 字，自動確保包含樹的短標題或核心詞）
        - `"scenes"`: 長度固定為 3 的陣列，依序為：
          1. `blueprint = "process_diagram"`：須提供 `title` (1..16字)、`caption` (20..120字)、`labels` (1..4個 `{text, tone}`)、以及 `params`（必須明確提供 `source: {label, fill}`、`container_layers` 2..4 層之 `{label, fill, weight, keep}`、`step_labels` 3 個步驟文字；`particles` 選填或預設 6）。
          2. `blueprint = "contrast"`：須提供 `title`、`caption`、`labels`、以及 `params`（必須明確提供 `left: {title, note, mode, core_effect, core_label, footnote, unit_fill}` 與 `right: {title, note, mode, footnote, unit_fill}`；`rows=3, per_row=5` 可預設）。
          3. `blueprint = "timeline"`：須提供 `title`、`caption`、`labels`、以及 `params`（必須明確提供 `milestones` 3 個階段文字、`unit_effect`、`connectors`、`unit_fill`；`units=3` 可預設）。且場景 3 的 `caption` 必須包含「因人而異」或「由醫師評估」等合規收尾語意。
    - `parse_and_build_tree_ir(raw: str, topic_key: str, fallback_title: str) -> tuple[dict | None, str]`：
      * 去除 `<think>...</think>` 與 markdown code fence（````json ... ````），解析 JSON。
      * **強制檢查零預設文字污染**：逐一檢查上述 3 個場景的文字型 `params` 欄位（`source.label`, `container_layers[].label`, `step_labels`, `left.title/note/core_label/footnote`, `right.title/note/footnote`, `milestones`）皆由模型實際提供且非空，絕不從 `BLUEPRINTS[bp]["defaults"]` 繼承任何預設中文字串！僅數值/配置欄位（`particles=6`, `rows=3`, `per_row=5`, `units=3`, `duration_sec=8`）在模型未提供時補安全整數常數。
      * 檢查所有文字欄位（`title`, `keywords`, 各場景 `title`, `caption`, `labels[].text`, 以及 `params` 內所有文字）皆不含阿拉伯數字（`\d`），並呼叫 `validate_ir(ir)` 完整驗證。
      * 失敗回傳 `(None, error_code)`（固定英文代碼，不含原文）。
    - `autodraft_from_tree(conn, tree_id_or_dict, llm_call=None, *, max_attempts=2, db_path=None, commit=True) -> dict`：
      * 檢查目標樹是否已核准（未找到回 `{"status": "not_found", "code": "tree_not_found"}`，未核准回 `{"status": "error", "code": "tree_not_approved"}`）。
      * 排程互斥：檢查 `nightly_batch_running(db_path)` 與非阻塞 `GENERATION_LOCK.acquire(blocking=False)`，忙碌回 `{"status": "busy", "code": "busy"}`。
      * 最多呼叫 `llm_call` `max_attempts`（預設 2）次；若 `LocalLLMUnavailableError` 則回 `{"status": "error", "code": "llm_unavailable"}`。
      * 驗證通過後，組裝 `asset = {"clinic_id": tree.get("clinic_id"), "topic_key": topic_key, "title": ir["title"], "keywords": ir["keywords"], "ir": ir, "metadata": {"origin": "pageindex_tree", "tree_id": tree["id"], "doc_id": tree["doc_id"], "tree_version": tree.get("content_version", 1)}}`。
      * 呼叫 `upsert_assets(conn, [asset], source_type="llm_generated", commit=commit)` 寫入，回傳 `{"status": "ok", "topic_key": topic_key, "clinic_id": tree.get("clinic_id"), "review_status": "pending", "ir": ir, **upsert_res}`。
