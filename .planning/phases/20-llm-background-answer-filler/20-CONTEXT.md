# Phase 20 Context: LLM 空閒時間衛教答案自動生成器

## 1. 業務背景與臨床痛點
在 Phase 18 與 Phase 19 實機上線後，醫師與行政人員實際上傳了診所原廠指引與常見問題文件（如「微創旋轉切除刀在乳房腫瘤檢測和診斷中的應用價值」、「Endolift - 指示 50」等）。目前資料庫中累積了 **176 筆** 待補齊答案的題目（ID 657 等）。

- **臨床痛點**：
  若由人工在 Web 介面上一張一張卡片點擊「🤖 生成解答」，176 題需要人員守在螢幕前點 176 次、等待將近 3 小時，耗費大量門診行政時間。
- **核心價值與目標**：
  建置 **「雙軌背景自動補齊機制」**：
  1. **Web 即時背景佇列**：上傳完成後，點擊【🚀 一鍵背景自動補齊所有答案】，後端以背景單佇列（Serial Queue）在背景一題接一題默默生成，人員可自由關閉視窗，畫面顯示即時進度條。
  2. **夜間批次離峰排程**：每日凌晨 02:30 定時批次執行時，自動掃描所有 `needs_answer=1` 的待審題目並徹夜生成完畢，醫師晨間打開即可直接審閱。

## 2. 核心規範與多 Agent 流水線（User Golden Rule）
依據使用者明確指定的不可動搖鐵則：
- **實作端 (Executor)**：一律由 **Agy 3.6 Flash (`w5:p2`)** 負責編寫後端 Worker、API 端點、前端進度元件與初始測試。
- **審查加固端 (Reviewer & Hardener)**：一律由 **Claude 5.5 Sonnet (`w5:p3`)** 進行深度對抗性代碼審查，重點防護：Worker 執行緒安全、單例鎖防重疊、GPU 資源保護、例外復原與 `AGENTS.md` 規範文檔同步。
- **終端驗收端 (Tester)**：一律由 **Hermes Agent (`w5:p4`)** 進行終端獨立全套回歸測試驗收與正式庫 SHA-256 防禦檢核。

## 3. 邊界與安全準則（Guardrails）
1. **GPU 顯存與資源保護（Serial Queue）**：
   - 本機僅有一張主要的 RTX 2080 Ti，背景生成必須採**單執行緒序列執行（一次只推論 1 題）**，嚴禁多執行緒並發打爆 VRAM。
2. **Fail-Closed 審核隔離不變**：
   - 背景補齊生成的答案，狀態**恆為 `pending`**，絕對不會直接跳過醫師核准。在醫師於 Web App 上「批量核准」前，對公開端點絕對不可見。
3. **醫療法規四層防護**：
   - 每題自動生成答案均須強制通過 `deep_mask_prices()` 價格清洗、正體中文檢核、無保證療效、包含就醫警訊。
4. **正式庫絕對安全**：
   - 測試全程使用 `tmp_path`，正式資料庫 `clinic.db` 不受測試污染。
