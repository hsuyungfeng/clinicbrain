# Phase 26 · Plan 01：「先答後導」病人諮詢流程（階段一，不收集個資）

> 由使用者於 2026-10-16 提出技能方向；本計畫為輕量規劃（未啟動完整 GSD researcher/planner 代理）。
> 所有說明與回報請使用繁體中文。

## 目標

建立病人端「先答後導」諮詢流程的規格與可測試的路由邏輯。病人先得到已核准資料的答案，沒有資料時得到誠實說明與預約方式，全程不收集姓名、電話、身分證資料，也不保存對話內容。


## 使用者決定（2026-10-16，待確認後執行）

- **C1（已決定，需修改規則）**：沒有資料時，先由本機 LLM 生成一般醫學說明，並建議洽詢合作診所（未來轉介），**同時**把問題送進草稿佇列給醫師審核。
  - 衝突：AGENTS 2.9、2.10 規定 LLM 生成內容在醫師核准前不得對外。實作前必須在 AGENTS 明文寫下例外，並限定：只限一般醫學知識、標示「一般知識，非本診所醫師意見，尚未經醫師審核」、附就醫警訊與免責聲明、不得含價格與用藥劑量。
  - 待確認：是否同意改規則。
- **C2（已決定，需確認個資條款）**：預約方式提供已完成的自願留資表單（截圖：植髮中心 · M型禿/髮際線高）。
  - 衝突：表單收集身分證末四碼、照片、生日、電話，且由第三方服務（底部顯示 powered by 便利診）承載。
  - 待確認：(a) 表單網址與營運者；(b) 同意條款與保存期限是否符合個資法；(c) 本系統只提供外部連結，不接收、不儲存任何表單資料，除非另行決定。
- **合作診所轉介**：先只在文字中提及「洽詢合作診所」，不建立轉介資料表（未來階段）。

## 原衝突紀錄（已由上方決定取代）

- **C1 · 即時 LLM 答案不得直接給病人**：審核閘門規定 LLM 生成內容須醫師核准後才對外（AGENTS 2.9、2.10）。本計畫採用的方式：沒有資料時，不即時生成答案，只回覆「目前沒有已核准資料」並建議洽詢診所，同時把問題送進一般草稿佇列（`pending`）等醫師審核。**若要改為即時 LLM 回答，須另行決定並修改審核規則，本計畫不做。**
- **C2 · 留資表單不屬於階段一**：階段一的預約只提供電話、LINE、官網預約連結，不提供表單。目前截圖中的表單會收集身分證末四碼與照片，屬階段二，且需法規與醫師確認。

## 路由順序（固定，不可調換）

1. **紅旗**（`detect_red_flag`）：直接回固定就醫指示，不查資料、不呼叫模型。
2. **已核准診所專屬 FAQ**（`special`，須指定 `clinic_id`）：有命中則回答並附來源。
3. **已核准一般衛教 FAQ**（`general`，`clinic_id IS NULL`）：有命中則回答並附免責聲明。
4. **沒有資料**：回覆固定說明文字（不即時生成），附預約方式，並把問題送進一般草稿佇列（待醫師審核；此步不影響回覆內容）。
5. **預約方式**：固定文字，只含電話、LINE、官網連結，來源為 `clinic_info`（電話與官網，不含醫師資料）。

## 任務

### T1 規格文件
- 新增 `docs/skills/patient-consult-stage1.md`：路由順序、固定文字、禁止事項（價格、療效保證、藥名與劑量、處方建議、醫師姓名）、個資規則（不問姓名電話、不存對話、不記錄問句原文）。
- 文件須列出「醫療廣告禁止用語」清單（如「保證」「根治」「100%有效」「限時優惠」「最低價」），並標註來源為既有禁詞規則與醫療廣告規範，**不得自行引用未查證的數據**。

### T2 路由純函式（可測試）
- 在 `src/general/` 新增純函式，輸入問句與 `clinic_id`，輸出路由結果（`red_flag` / `clinic_faq` / `general_faq` / `no_data`），不得在此函式內呼叫 LLM。
- 沿用既有 `visible_faq_sql`，不得新增繞過審核的查詢。

### T3 草稿佇列（沒有資料時）
- 沒有資料時，把問題以一般草稿形式送進佇列：沿用 `generate_general_draft` 的去識別化，但**不生成答案**（只存問題，答案欄為空或標示「待醫師撰寫」）。
- 需先確認：`faq_cache` 的答案欄不得為空字串造成顯示錯誤（若不可行，改為獨立的「待答問題」表，此項列為決策點）。

### T4 測試
- 路由順序測試：紅旗優先於資料查詢；診所 FAQ 優先於一般 FAQ；未核准草稿不會被命中。
- 個資測試：路由與回覆不含使用者問句的識別資訊；日誌不記錄問句原文（沿用 `/general` 的零日誌規則）。
- 禁用語測試：固定回覆文字不含清單中的任何詞。

### T5 不做的事（明確排除）
- 不做即時 LLM 回答（見 C1）。
- 不做留資表單、不收集任何個資（見 C2）。
- 不做潛在客戶打分、不做自動銷售推播。
- 不做合作診所轉介（另列未來階段）。

## 驗收

- 規格文件存在且與程式行為一致（路由順序與固定文字）。
- 新增測試全部通過，回歸測試不退步。
- 正式庫 `clinic.db` SHA-256 不因測試改變。
- 回報：通過測試數、路由覆蓋的四種結果、未解決的決策點（C1、C2 與 T3 的答案欄）。
