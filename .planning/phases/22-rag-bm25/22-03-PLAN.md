# Plan 22-03: 前端顯示優化、端到端實機驗收與全套回歸防護

## 1. 目標
打通前端 Web 管理介面（`💬 向 LLM 提問` 分頁）的結構化呈現，串接實體本機 Qwen-27B 進行「甲溝炎要怎麼照護？」真實問答驗收，並由 Claude 5.5 進行對抗性加固與終端回歸測試驗證。

## 2. 實作任務（多 Agent 流水線）
1. **前端 Web App 呈現微調 (`src/web/static/app.js`, `style.css`)**：
   - 調整 `renderAskResult`：支援結構化段落（分行、加粗標籤【門診處置】、【日常照護】、【就醫提醒】）更清晰美觀之排版。
   - 資料來源列表呈現：當來源筆數增至 6~8 筆時，提供清晰且緊湊的晶片標籤（Chips）或折疊檢視。
2. **對抗性審查與邊界加固（指派 Claude 5.5 Sonnet `w5:p3`）**：
   - 審查 BM25 subquery JOIN 是否在各種複雜 `extra_where` 或特殊符號下產生 SQL 語法錯誤。
   - 審查擴大 Context 是否存在價格數字、未遮蔽隱私資訊被模型回吐之風險。
   - 審查結構化分段與 250~400 字放寬是否會導致 DX-4/5 給藥動詞誤觸發或漏檢。
3. **端到端實機測試 (`tests/test_phase22_e2e_acceptance.py`)**：
   - 針對真實問句「甲溝炎要怎麼照護？」執行端到端檢驗。
   - 斷言：檢索來源包含門診手術與居家照護（如 ID 497 等），模型輸出條列結構，句末標註引用來源，合規檢核通過。
4. **終端全套回歸測試驗收**：
   - 執行既有全套測試（web UI、medical safety、admin API、pageindex trees）。
   - 確保正式庫 `clinic.db` SHA-256 恆定未變、零資料污染。

## 3. 驗收標準
- `pytest tests/test_rag_bm25_retrieval.py tests/test_rag_ask_enhancement.py tests/test_phase22_e2e_acceptance.py` 全部 PASS。
- Web UI 提問「甲溝炎要怎麼照護？」成功輸出含【門診處置】與【日常照護】之結構化專業衛教。
