# Plan 22-02: 提問檢索 Context 召回擴充與結構化衛教 Prompt 優化

## 1. 目標
調整 `src/pageindex/rag_ask.py` 的檢索召回視野與 Prompt 工程，使本機 LLM 在為醫師／病患提供衛教問答時，能基於更寬廣的真實已核准 Context 生成結構完整、條理分明且符合台灣醫療法規的衛教指南。

## 2. 實作任務（指派 Agy 3.6 Flash）
1. **擴大檢索召回視野 (`src/pageindex/rag_ask.py`)**：
   - 將 `MAX_FAQ` 常數由 `4` 擴增至 `8`（提供更全面的診所門診與生活照護 Context）。
   - 保留 `MAX_TREES = 2`、`SNIPPET_CHARS = 500`。
   - 評估整體 Context 長度：8 筆 FAQ（約 1,600~2,400 字）+ 推理樹，在 Qwen 128k 視窗下占用約 2,000 tokens，遠在安全負載之內。
2. **優化衛教 Prompt 模板 (`build_ask_prompt`)**：
   - 調整回答字數區間：由原 `約 100～250 字` 放寬為 `約 250～400 字`。
   - 強化結構化引導：指示模型在資料充足時，依主題按分段條列說明（例如【門診處置】、【日常照護】、【就醫提醒與預防】），提升病患閱讀易讀性。
   - 嚴格維持 7 大守則：
     1. 只能根據下方資料回答，不可使用資料外醫學知識，不可臆測。
     2. 資料不足時誠實告知「目前資料中沒有足夠資訊回答這個問題，建議洽詢診所醫師」。
     3. 句末明確引用資料來源編號 `[F1]`、`[T1]` 等。
     4. 嚴格禁止出現任何金額、價格、折扣。
     5. 嚴格禁止出現具體藥品名稱與劑量，不下診斷、不開處方。
     6. 不得使用保證療效詞彙。
     7. 結尾必須以具體症狀警訊提醒何時應儘速就醫。
3. **單元測試驗證 `tests/test_rag_ask_enhancement.py`**：
   - 測試 Context 擴充至 8 筆時檢索與格式解析正確無誤。
   - 測試 Mock LLM 結構化輸出能順利通過 `validate_single_faq` 醫療法規檢核。
   - 測試若資料來源不足時仍能觸發誠實無資料機制。

## 3. 驗收標準
- `pytest tests/test_rag_ask_enhancement.py` 全部通過。
