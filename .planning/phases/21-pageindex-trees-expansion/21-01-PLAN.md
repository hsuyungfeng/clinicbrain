# Plan 21-01: 臨床決策推理樹審核架構、提煉管線與後端 API

## 1. 目標
在 `page_index_trees` 建立完整的審核狀態（`review_status`）與醫師簽核機制，實作長文提煉四段式臨床推理樹的 LLM 引擎，並在 `src/api/routes/admin.py` 提供完整的樹狀決策管理 API。

## 2. 實作任務（指派 Agy 3.6 Flash）
1. **資料庫結構擴充與遷移**：
   - 建立 `scripts/migrate_page_index_review.py`：冪等為 `page_index_trees` 增加 `review_status` (DEFAULT 'approved')、`reviewed_at`、`reviewed_by`、`title` 欄位。
   - 同步更新 `src/db/clinic_schema.sql`，確保新建庫具備相同結構與索引。
2. **核心審核模組 `src/pageindex/tree_review.py`**：
   - 實作 `has_tree_review_status(conn) -> bool`。
   - 實作 `visible_tree_sql(conn) -> str`：Fail-Closed 篩選，未審核之草稿對外一律隔離。
   - 實作 `list_trees(...)`, `get_tree(...)`, `update_tree(...)`, `approve_tree(...)`, `reject_tree(...)`, `delete_tree(...)`, `count_trees_by_status(...)`。
3. **擴充權威寫入 `src/pageindex/db_writer.py`**：
   - `CONTENT_FIELDS` 加入 `title`（若提供）。
   - 支援寫入 `review_status`（手寫預設 `approved`，自動提煉預設 `pending`）。
4. **臨床推理樹提煉器 `src/pageindex/tree_distiller.py`**：
   - 自輸入長文或上傳檔案中提取重點，組裝 prompt。
   - Prompt 第一條嚴格限制思考長度（不超過 100 字）。
   - 四段式輸出結構解析：`pre_op`, `procedure`, `post_op_short`, `maintenance`, `summary_text`。
   - 強制留空所有 `*_physician_notes`，強制通過繁體中文、無價格洩漏、無保證療效檢核。
   - 呼叫權威寫入函式 `upsert_trees` 寫入為 `source_type='clinic_upload'` 或 `'web_upload'`，`review_status='pending'`。
5. **檢索可見性隔離 `src/query/search.py`**：
   - `search_page_index_trees` 引入 `visible_tree_sql(conn)`，確保未核准樹無法被 RAG / handle_query 檢索。
6. **後端 Admin API 端點擴充 (`src/api/routes/admin.py`)**：
   - `GET /api/v1/admin/trees`：列表查詢（支援 status, category, clinic_id 篩選）。
   - `GET /api/v1/admin/trees/{tree_id}`：單一推理樹詳情。
   - `POST /api/v1/admin/trees/distill`：由長文或文件提取生成待審推理樹。
   - `PUT /api/v1/admin/trees/{tree_id}`：編輯各段文字與填寫醫師權威醫囑 (`*_physician_notes`)。
   - `POST /api/v1/admin/trees/{tree_id}/approve`：醫師簽核核准。
   - `POST /api/v1/admin/trees/{tree_id}/reject`：駁回草稿。
   - `DELETE /api/v1/admin/trees/{tree_id}`：刪除草稿。
7. **測試編寫 `tests/test_tree_review_backend.py`**：
   - 驗證遷移、Fail-Closed 搜尋隔離、提煉合規性檢核與簽核生命週期。

## 3. 驗收標準
- `pytest tests/test_tree_review_backend.py` 全部通過。
