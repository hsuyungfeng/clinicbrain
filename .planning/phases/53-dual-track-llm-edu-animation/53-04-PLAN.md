# Plan 53-04: 全庫 398～400 筆批次生成、重點 MP4 重渲與 Hermes 驗收（Wave 4）

## Goal
執行全庫 398 筆 `visual_assets` 的斷點續跑 Local LLM 批次生成，重渲代表性主題 MP4（並視排程重渲全庫），重啟 API 服務並交由 Hermes 獨立驗收整個雙軌系統。

## Tasks

### Task 1: 執行全庫可斷點續跑批次生成
- 執行 `.venv/bin/python3 scripts/generate_edu_batch.py --all --resume`（針對 `edu_json IS NULL` 之項目依序生成並寫入 `clinic.db`，每筆即時 commit，支援中斷續跑與單筆重試）。
- 批次結束後執行 `.venv/bin/python3 scripts/audit_db_visual_assets.py --strict`，確認全庫 `錯配數: 0`。

### Task 2: 重渲代表性主題 MP4 與重啟 API 服務
- 對代表性主題（大腸憩室病 + Phase 52 9 支關鍵主題）執行 `.venv/bin/python3 scripts/run_video_render_queue.py --topic-key ... --aspect landscape`（驗證含 `care_redflag` 第 3 幕之新 MP4 與新 `visual_engine.js` salt 快取雜湊）。
- 若背景 API 伺服器（`127.0.0.1:8002`）已運行，重啟以載入新路由 `/edu/{topic_key}` 與 `/api/v1/visual/edu/{topic_key}`。

### Task 3: Hermes 獨立 Tester 驗收
- 透過 `herdr` 指派 Hermes 執行實機驗收：
  1. `audit_db_visual_assets.py --strict`（0 錯配）與 DB `edu_json` 覆蓋率檢查。
  2. 執行 `pytest tests/test_care_redflag_blueprint.py tests/test_edu_generator.py tests/test_edu_web_endpoints.py tests/test_visual_assets_deep_audit.py -q`。
  3. 實測 `http://127.0.0.1:8002/edu/{topic_key}` 與 `/api/v1/visual/edu/{topic_key}`（大腸憩室病 + 口腔念珠菌症），確認無簡體字、無價格洩漏、7 段內容完整且 SVG 3 幕無 JS 錯誤。
