# 46-01-PLAN: P0 回歸修復、安全 DOM 重構與資料庫結構同步

## 1. 目標 (Objective)
解決體檢中確認之 P0 阻斷性問題：修復 `app.js` 違反第 7 區純 textContent 安全不變量的 `innerHTML` 漏洞與寫死 88 筆文字；修復 `runner.py` 批次錯誤統計與影片階段連坐失敗；在正式 `clinic.db` 中補齊 `sync_logs` 資料表與索引，並在寫入連線啟用 `busy_timeout`。

## 2. 交付成果 (Deliverables)
1. **前端純 DOM 重構 (`src/web/static/app.js`)**：
   - 將第 7 區（向 LLM 提問）中的 `emptyBox.innerHTML = ...` 改寫為標準 `el(...)` / `document.createElement` + `textContent`。
   - 移除寫死之 `(88 筆)`，改為讀取當前總數或語意化標題「👉 立即查看已發布決策樹」。
   - 通過 `tests/test_admin_ask.py::test_ui_has_ask_tab_and_no_html_injection`。
2. **夜間批次錯誤統計解耦 (`src/batch/runner.py`)**：
   - 檢視 `BatchConfig.skip_video_render` 預設值，設定測試或非顯式啟用環境下不連坐累積主知識庫 `summary.errors`。
   - 確保批次總錯誤數僅反映臨床衛教與推理樹提煉之成敗，影片渲染失敗維持獨立 `videos_failed` 統計。
   - 通過 `tests/test_batch_runner.py::test_rejected_items_do_not_cause_topic_failure`。
3. **資料庫結構與並發防禦補齊 (`clinic.db` & `src/api/dependencies.py`)**：
   - 對正式 `clinic.db` 執行 DDL，建立與 `clinic_schema.sql` 完全一致的 `sync_logs` 資料表與索引。
   - 在 `get_write_db()` 中加入 `conn.execute("PRAGMA busy_timeout = 5000;")`，降低並發寫入時鎖競爭風險。

## 3. 驗收標準 (Acceptance Criteria)
- [ ] `tests/test_admin_ask.py` 執行 100% 通過（零 `innerHTML` 誤用）。
- [ ] `tests/test_batch_runner.py` 執行 100% 通過（`summary.errors == 0`）。
- [ ] `clinic.db` 包含 `sync_logs` 表，`GET /api/v1/sync/logs` 唯讀連線正常回傳空串列，不拋 500。
- [ ] 寫入連線具備 5 秒 busy timeout。
