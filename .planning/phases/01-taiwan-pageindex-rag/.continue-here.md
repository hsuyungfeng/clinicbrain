# BLOCKING CONSTRAINTS — Read Before Anything Else

> These are not suggestions. Each constraint below was discovered through failure.
> Acknowledge each one explicitly before proceeding.

- [ ] CONSTRAINT: OTC Localization Scope — All drug ingredient references in LLM output must be automatically localized (乙醯胺酚→普拿疼的乙醯胺酚, 布洛芬→常見的布洛芬). Missing this causes non-compliant medical advice.
- [ ] CONSTRAINT: Price Masking Rule — Absolute prohibition on any raw price numbers in outputs. All monetary references must be → `[請致電診所確認]`. Discovered through failed queries where prices leaked.
- [ ] CONSTRAINT: 繁體中文 Exclusive — Every LLM output must use繁體中文 only. English or simplified Chinese outputs violate compliance requirements.
- [ ] CONSTRAINT: FTS5 Chinese Tokenizer — SQLite FTS5's `unicode61` tokenizer does NOT segment CJK text; it was found silently broken on `page_index_fts` even after `drugs_fts`/`service_items_fts` had already been fixed to `trigram` — any new/changed FTS5 virtual table in this project MUST explicitly set `tokenize='trigram'` and be verified with a real Chinese-language MATCH query before being considered done. Never assume a schema-level fix propagated everywhere; grep `sqlite_master` for `fts5` to confirm.
- [ ] CONSTRAINT: Record-count sanity — `wc -l` on these CSVs does NOT equal record count (multi-line free-text fields like AI-note/給付規定 contain embedded newlines). Always verify counts via `csv.DictReader` row iteration, not `wc -l`, before treating a low import count as a bug.

**Do not proceed until all boxes are checked.**

## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Price Leakage | Raw TWD prices (e.g., "1500元", "NT$500") appear in LLM reasoning responses | blocking | Post-process all output through regex mask: `\$\d+(?:,\d+)*[元塊]?` → `[請致電診所確認]` |
| Route Confusion | `general` route incorrectly includes clinic hours/info from SQL database | blocking | Strict `special`/`general` keyword filtering before context gathering |
| Language Drift | Mixed simplified/traditional Chinese in outputs | blocking | Pre-prompt enforcement + post-output verification; note the SFT dialogue corpus (medical_o1_sft_Chinese.json) is Simplified Chinese — never feed it directly into any Traditional-Chinese-only pipeline |
| Silent FTS5 tokenizer drift | Adding/editing an FTS5 virtual table without explicitly re-specifying `tokenize='trigram'` silently reverts to `unicode61` default, which cannot match CJK text at all | blocking | Always grep `sqlite_master` for all `fts5` tables after any schema change and run a live Chinese MATCH query per table |
| CSV row-count miscounting | Using `wc -l` to estimate CSV record counts when fields contain embedded newlines | advisory | Count records via `csv.DictReader`, not `wc -l` |

**Severity values:** `blocking` — resuming agent must pass understanding check before proceeding. `advisory` — important context, does not gate resumption.

<decisions_made>

- Decided to use dual-layer architecture: General NHI data (OriginalData) + Clinic-specific data (per-clinic DB) because it separates concerns and allows independent updates
- Chose route-based context gathering over single unified context because it prevents information overload and ensures clinic-specific data doesn't leak into general queries
- Implemented absolute price masking rule because Taiwan medical compliance prohibits any price information in AI outputs
- Selected繁體中文 as exclusive output language for compliance with Taiwan medical regulations
- Designed OTC localization as hardcoded mapping for reliability, with future expansion capability from NHI database
- Resolved the single-DB-vs-per-clinic-DB blocker implicitly by implementation: single SQLite DB with `clinic_id` columns on clinic-specific tables (see `src/db/clinic_schema.sql`) — never explicitly re-litigated, just built this way and it works
- Chose `tokenize='trigram'` for all FTS5 tables over `unicode61` (cannot segment CJK at all) and over a jieba-based custom tokenizer (adds a dependency, higher maintenance) — trigram plus a LIKE fallback for sub-3-character queries was judged sufficient at current data volume (~10K rows total)
- Chose NOT to auto-generate PageIndex trees from existing data sources (SFT dialogue data is Simplified Chinese TCM Q&A — wrong language and wrong domain; service_items payment_rules is generic boilerplate with no clinical steps). Hand-wrote seed trees instead, to serve as the few-shot quality baseline TASK-004's LLM prompt will be built and evaluated against.
</decisions_made>
