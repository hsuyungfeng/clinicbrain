# Plan 48-02: 每日趨勢與 Gap Checker (`src/batch/gap_checker.py`)

## Objective
實作 `src/batch/gap_checker.py` 與執行腳本 `scripts/run_daily_gap_check.py`，整合 Plan 48-01 產出的診所高頻 ICD-10 疾病與每日網路醫療熱搜主題，盤點既有 `faq_cache` 與 `page_index_trees` 是否已備妥一般醫學對話（`covered` / `partial` / `uncovered`），並將缺漏題單透過唯一寫入路徑 `faq_writer.upsert_faqs()` 送進「📝 待審衛教草稿簽核」待審隊列。

## Tasks

### Task 1: 實作每日網路趨勢擷取與疾病問題推演
- **File**: `src/batch/gap_checker.py`
- **Details**:
  1. 定義 dataclass：`TrendTopic`（`title`, `topic_key`, `icd10`, `source_name`, `source_url`, `questions`, `clinic_rank`）、`GapItemReport`（`topic_key`, `title`, `status` [`covered`/`partial`/`uncovered`], `existing_questions`, `missing_questions`, `icd10`, `sources`）、`GapCheckReport`。
  2. 實作 `fetch_daily_health_trends(urls: Sequence[str] = (), *, fetcher: Optional[Callable[[str], str]] = None, allowlist_path: Optional[Path] = None, max_items: int = 10) -> list[TrendTopic]`：
     - 若未提供 `fetcher` 且 `urls` 非空，透過 `src/scraper/policy.py`（`validate_url_safety` / HTTPS / SSRF 防護）安全抓取公開頁面或 RSS/Atom XML 標題與摘要。
     - 強制經 `to_traditional()`、`deidentify_text()` 與 `deep_mask_prices()` 清洗。
  3. 實作 `derive_patient_questions(title: str, *, extra_questions: Sequence[str] = (), llm_call: Optional[Callable[[str], str]] = None) -> list[str]`：
     - 基底套用 `src.batch.patient_prefill_plan.INTENT_TEMPLATES` 展開 5 大標準問題。
     - 若有 `extra_questions`（如網路熱搜擷取到的常見提問）或 `llm_call`，補充口語化常見問題並經 `validate_single_faq` 題目合規檢核與去重。

### Task 2: 實作覆蓋率盤點 (`covered` / `partial` / `uncovered`) 與待審佇列寫入
- **File**: `src/batch/gap_checker.py`
- **Details**:
  1. 實作 `check_topic_coverage(conn, topic: TrendTopic) -> GapItemReport`：
     - 查詢 `faq_cache`（`category = 'general'` 且 `review_status IN ('approved', 'pending')`）：
       - 優先依 `topic_key` 精確查詢；
       - 同步以 `topic.title` 透過 `faq_cache_fts`（3+ 字 `MATCH`）或 `LIKE ... ESCAPE '\'`（<3 字，重用 `escape_like`）撈取相關一般醫學問答，避免不同 `topic_key` 重複建題。
     - 檢查 `page_index_trees`（重用 `visible_tree_sql`）是否已有對應一般醫學推理樹。
     - 逐題比對 `topic.questions` 與既有問題（NFKC 正規化、去標點與語助詞後精確匹配或高字元重疊率 `>= 0.85` 視為已覆蓋）。
     - 判定狀態：全部覆蓋 → `covered`；部分題目缺失 → `partial`；完全無既有問答 → `uncovered`。
  2. 實作 `run_gap_check(conn, *, clinic_id: Optional[str] = None, aggregated_icd10: Optional[Sequence[dict]] = None, trend_topics: Optional[Sequence[TrendTopic]] = None, trend_urls: Sequence[str] = (), fetcher: Optional[Callable[[str], str]] = None, llm_call: Optional[Callable[[str], str]] = None, dry_run: bool = False, max_topics: int = 10) -> GapCheckReport`：
     - 呼叫 `get_top_clinic_diseases()` 取得診所高頻 ICD-10 疾病，與 `trend_topics` / `fetch_daily_health_trends()` 合併去重。
     - 對每個主題執行 `check_topic_coverage()`，彙整 `covered` / `partial` / `uncovered` 計數與明細。
     - 若 `not dry_run`，將 `partial` 與 `uncovered` 的 `missing_questions` 組裝為待審 FAQ：
       - 若有 `llm_call`，呼叫 `generate_topic_faqs` 生成合規繁體解答；若無 `llm_call`（純題單推送模式），填入標準待補佔位解答並於 `metadata` 標記 `"needs_answer": true`（供 Web 介面「一鍵背景自動補齊所有答案」接手）。
       - 寫入一律呼叫 `faq_writer.upsert_faqs(conn, rows, source_type="llm_generated")`，確保 `category='general'`、`clinic_id=None`、`review_status='pending'`。

### Task 3: 建立獨立 CLI 入口與隔離單元測試
- **Files**: `scripts/run_daily_gap_check.py`, `tests/test_gap_checker.py`
- **Details**:
  1. `scripts/run_daily_gap_check.py`：支援 `--db`、`--clinic-id`、`--icd-json`（匯入聚合診斷碼檔）、`--dry-run`、`--json` 輸出報表摘要；預設不主動連網（需明確傳入 `--trend-url`）。
  2. `tests/test_gap_checker.py`：
     - 測試 `covered` / `partial` / `uncovered` 三種狀態判定準確性（包含 `approved` 與 `pending` 皆算已排程覆蓋、`<3` 字短詞 `LIKE` fallback、`3+` 字 `FTS5`）。
     - 測試 `dry_run=True` 時絕不寫入資料庫。
     - 測試 `dry_run=False` 時透過 `faq_writer.upsert_faqs(source_type='llm_generated')` 寫入，新列恆為 `review_status='pending'`、`category='general'`、`clinic_id IS NULL`，且 `metadata` 含正確溯源 JSON。
     - 測試注入含簡體字/價格數字/個資的模擬網頁內容時，均被正確轉換/清洗/遮罩。
