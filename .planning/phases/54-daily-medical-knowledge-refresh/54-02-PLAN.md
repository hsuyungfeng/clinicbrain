# Plan 54-02: 本機 LLM 實質差異比對器與每日輪巡排程（Wave 2）

## Tasks

### Task 1: 實作 `src/refresh/detector.py`
- 實作輪巡選題器 `select_refresh_candidates(conn, daily_quota: int = 15)`：
  - 優先納入近 7 日 `cache_stats` (`outcome='miss_keyword'`) 高頻未命中關聯之已核准項目，再依 `knowledge_refresh_log.last_verified_at ASC NULLS FIRST` 輪巡 `faq_cache`、`page_index_trees`、`visual_assets`（僅限 `review_status = 'approved'`）。
  - 跳過已經有同 `target_type + target_key` 且 `status = 'pending'` 尚未審核的項目，避免重複累積待審提案。
- 實作 `evaluate_and_propose(conn, candidate, evidence_list, llm_call=None, dry_run=False)`：
  - 呼叫 `local_llm_call()` 輸出嚴格 JSON：`{"has_material_change": bool, "diff_summary": str, "proposed_payload": dict}`。
  - 若 `has_material_change` 為 `False`，僅更新 `knowledge_refresh_log` (`last_status='unchanged'`)。
  - 若為 `True`，依 `target_type` 執行結構驗證與合規過濾（`opencc s2twp` + `deep_mask_prices` + 禁詞/政治敏感詞；`visual_edu` 驗證 `EduContent` Schema；`tree` 移除任何 `*_physician_notes` 欄位），寫入 `knowledge_refresh_proposals (status='pending')` 並更新 `knowledge_refresh_log` (`last_status='proposed'`)。

### Task 2: 建立每日排程腳本 `scripts/run_daily_knowledge_refresh.py`
- 支援 CLI 參數：`--db`、`--daily-quota`（預設 15）、`--target-type`（`all | faq | tree | visual_edu`）、`--topic-keys`、`--check-feeds`、`--dry-run`。
- 執行完畢印出統計（檢核筆數、無異動、新增提案數、錯誤數），並確保不自動簽核任何提案。

### Task 3: 建立 `tests/test_refresh_detector.py`
- 以 Mock LLM + Mock HTTP 測試：① 無實質變動僅記 `unchanged` 不產提案；② 有實質變動產出 `pending` 提案且經繁體化/價格清洗；③ 含禁詞/簡體字提案被攔截；④ `tree` 提案不含 `*_physician_notes`、`visual_edu` 不含 `organ_system` 覆寫。
