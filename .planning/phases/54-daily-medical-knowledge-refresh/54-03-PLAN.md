# Plan 54-03: 管理後台 Diff 簽核 API 與權威寫入連動（Wave 3）

## Tasks

### Task 1: 實作 `src/refresh/applier.py`（唯一權威寫入橋接）
- `approve_proposal(conn, proposal_id: int)`（**單一交易 `commit=False` 原子更新**）：
  - 檢查提案存在且 `status == 'pending'`（否則拋錯回傳 404/409）。
  - `target_type == 'faq'`：從 `faq_cache` 讀取原列之 `clinic_id`、`topic_key`、`category`、`question`、`source_type`，組裝完整 FAQ dict 呼叫 `src.pageindex.faq_writer.upsert_faqs(conn, [faq], source_type=orig_source_type, commit=False)`（遞增 `content_version`），並於同交易內確保 `review_status = 'approved'`、`reviewed_at = CURRENT_TIMESTAMP`。
  - `target_type == 'tree'`：從 `page_index_trees` 讀取既有列之 `source_type` 與全部 4 個 `*_physician_notes` 欄位（不可缺鍵以免 `CONTENT_FIELDS` `KeyError`），與提案的四段內容合併後呼叫 `src.pageindex.db_writer.upsert_trees(conn, [tree], source_type=orig_source_type, review_status='approved', commit=False)`（保留醫師筆記與原 `source_type`）。
  - `target_type == 'visual_edu'`：驗證 `EduContent`、於同交易以 `UPDATE visual_assets SET edu_json = ?, edu_updated_at = ?, ir_json = ?, content_version = content_version + 1, updated_at = CURRENT_TIMESTAMP WHERE topic_key = ? AND clinic_id IS ?`（禁止 `INSERT OR REPLACE`）寫回，並以 `build_upgraded_ir(existing_ir, edu)` 鎖定 `organ_system`/`anatomy_target`。
  - 同交易將提案標記 `status='approved', reviewed_at=CURRENT_TIMESTAMP` 後統一 `conn.commit()`。
- `reject_proposal(conn, proposal_id: int)`：標記 `status='rejected'`。

### Task 2: 新增管理後台路由 `src/api/routes/admin/refresh.py` 並掛載
- 於 `src/api/routes/admin/__init__.py` 掛載 `refresh_router`（受 `verify_admin_key` 與 `/admin` 安全標頭保護）；查詢端點使用 `Depends(get_read_db)`，核准/駁回/巡檢端點使用 `Depends(get_write_db)`。
- 提供：`GET /api/v1/admin/refresh/proposals`、`POST /api/v1/admin/refresh/proposals/{id}/approve`、`POST /api/v1/admin/refresh/proposals/{id}/reject`、`POST /api/v1/admin/refresh/run`（小批背景或同步試跑）。

### Task 3: 管理後台 UI 整合與 API 測試
- 於 `src/web/static/index.html` 與 `src/web/static/app.js` 新增「🔄 新知提案審核」頁籤／區塊（使用安全 `textContent` DOM 操作顯示 `diff_summary`、`source_url`、`current_snapshot` vs `proposed_json`，提供核准／駁回按鈕）。
- 建立 `tests/test_refresh_admin_api.py`（測試 list、approve 連動 `upsert_faqs`/`upsert_trees` 保留 `physician_notes`/`visual_edu` 鎖定解剖、重複核准 409、reject 與未認證 401）。
