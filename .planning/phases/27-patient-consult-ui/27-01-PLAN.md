## T1 病人諮詢頁（前端）
- 新增 `src/web/static/consult.html`（獨立頁，手機優先，16px 側邊留白，無水平捲動）。
- 元件：問題輸入框（最多 300 字，Enter 送出，Shift+Enter 換行）、送出鈕、結果區、「預約諮詢」按鈕連到 `https://doctor-toolbox.com/`（以回應的 `booking_url` 為準，不寫死）。
- 結果區依 `status` 顯示：`red_flag`（紅字就醫指示）、`answered`、`llm_general`（顯示 `label` 與 `disclaimer`）、`no_match`、`busy`。
- 送出中顯示「整理中，約 1～3 分鐘」；網路失敗顯示固定中文訊息。
- **隱私**：問題文字不得寫入 `localStorage`、`sessionStorage`、cookie、URL 或 console；送出後清空輸入框。
- **安全**：所有伺服器回傳內容一律以 `textContent` 寫入，不得使用 `innerHTML`、`insertAdjacentHTML`、`document.write`、`eval`。
- 掛載方式沿用 `/admin` 的靜態檔案服務（查 `src/api/app.py` 既有掛載）。

## T3 實機端對端驗證（使用副本資料庫）
- 先複製 `clinic.db` 為 `logs/e2e_copy.db`（**不得直接寫正式庫**）。
- 以副本啟動測試用 API（不同埠，例如 8011，指向 `logs/e2e_copy.db`），驗證：
  1. 紅旗問句（如「我胸痛呼吸困難」）→ `red_flag`，耗時短，無 LLM 呼叫。
  2. 罕見問題首次提問 → `llm_general`，副本中出現 1 筆 `pending` 一般草稿。
  3. 同一問題再問一次 → `llm_general` 且答案相同，**草稿筆數不增加**（驗證同題重用）。
  4. 駁回後同題再問 → `no_match`（需先在副本手動將該列設為 `rejected`）。
- 記錄每個步驟的 HTTP 碼、耗時與 `status`；完成後停止副本 API。
- 正式庫 SHA-256 前後必須相同。
