## 一、評估的兩個系統

1. **LLM-only**：`classify_scene1_blueprint`（目前提示詞 v2）對盲測表單每列的 `source_text` 產生預測。
2. **完整系統**：先 `lookup_blueprint(title, icd_name)`（TOPIC_BLUEPRINT_REGISTRY）；命中則預測為查表結果，
   未命中則走 LLM-only。預測結果需經過放行閘門，記錄 `accepted` 與否。

兩者都需要報告。

## 二、產出

- `scripts/predict_blind_set.py`
  - 讀取盲測表單（唯讀），對 30 列各跑 LLM-only 與完整系統，寫入
    `golden/blind_predictions.csv`（欄位：`tree_id, doc_id, llm_blueprint, llm_status, llm_confidence, llm_evidence, system_blueprint, system_source, system_accepted`）。
  - 本地 LLM 使用 `local_llm_call(prompt, timeout=420, sampling={"chat_template_kwargs": {"enable_thinking": False}})`，與截斷修正後的設定一致。
  - 盲測表單的 `title` 欄為 `doc_id`，預測時以 `doc_id` 作為標題傳入，並在 SUMMARY 註明此限制。
- `scripts/eval_blind_set.py`
  - 讀取 `blind_labeling_sheet.xlsx`（「標註」）與 `blind_predictions.csv`，計算：
    - A. LLM-only 原始準確率（30 筆）；
    - B. 完整系統原始準確率（30 筆，含查表命中與 LLM 結果）；
    - C. 完整系統自動接受準確率（僅 `system_accepted == True`）與自動接受率；
    - 每類召回率與精確率（13 類，分母為 0 顯示 N/A）、混淆矩陣、`other` 比例、`invalid_evidence` 數量。
  - 以 `--threshold 0.85` 顯示是否達標，但**門檻保持凍結**，報告中標明「不作為放行依據」。
  - 報告寫入 `golden/57-02-T6-BLIND-EVAL.md`。
- 測試：`tests/test_eval_blind_set.py`，至少覆蓋：分母為 0 的 N/A、未接受列不計入 C 分子、查表命中的 `system_source`、
  缺欄位與未標註列的退出碼。測試使用臨時檔案，不依賴盲測表單內容。
- `57-02-T6-SUMMARY.md`：列出指令、數字、與本計畫逐項對照。
