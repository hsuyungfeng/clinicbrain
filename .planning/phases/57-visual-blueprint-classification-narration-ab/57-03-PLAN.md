<objective>為每支動畫加入分場旁白（TTS）與 2–3 題理解題，並設計 A/B 測試（變項：有旁白 vs 無旁白；理解題成績為主要指標）。本階段完成離線評估與曝光設計；正式曝光需操作者核准。</objective>
<tasks>
<task id="T1"><name>旁白與字幕同步</name>
<action>採用「前端朗讀」方案（已決策，B-PRE-2）：旁白文字由各幕 `caption` 派生，由瀏覽器 Web Speech API 朗讀（zh-TW），不安裝任何本地 TTS 套件、不產生音檔。每幕時長以字數估算（演算法寫入 narration.py 並有測試）作為字幕段落的時間軸。前端需先偵測是否有 zh-TW 語音，無則退回純文字字幕且記錄於 A/B 分組條件。禁止阿拉伯數字（沿用 `_check_no_digits_recursive`）與禁詞。</action>
<acceptance_criteria>- 旁白文字通過數字與禁詞檢查（測試）；- 每幕時長估算函式以固定字數區間的測試案例驗證（測試）；- 本計畫不產出任何音檔（`find` 驗證 narration 輸出目錄無 .mp3／.wav）；- 前端無 zh-TW 語音時退回純文字字幕的分支有測試覆蓋。</acceptance_criteria>
</task>
<task id="T2"><name>理解題</name>
<action>由 LLM 依 caption 產生 2–3 題選擇題（含正解與解釋），題目與選項同樣經禁詞與數字檢查；正解必須能在 caption 中找到依據。</action>
<acceptance_criteria>- 每題正解的依據子字串存在於 caption（測試）；- 題數介於 2 與 3 之間；- 題幹不超過 40 字、每個選項不超過 20 字，超過即重新生成（對應 agy D4，測試覆蓋）。</acceptance_criteria>
</task>
<task id="T3"><name>A/B 設計文件</name>
<action>撰寫 57-03-AB-DESIGN.md：分組方式（隨機、以訪客 cookie 或 session，不記錄個資）、樣本數估算、主要指標（理解題正確率）、次要指標（完成率、停留）、停止規則、倫理與資料保存。正式曝光前交操作者核准。</action>
<acceptance_criteria>- 文件含樣本數計算過程與停止規則；- 文件明列「未核准前不曝光」。</acceptance_criteria>
</task>
</tasks>
