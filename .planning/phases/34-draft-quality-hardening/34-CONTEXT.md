# Phase 34 CONTEXT：49 筆推理樹動畫草稿品質強化

## 背景
- Phase 33 完成後，49 筆已核准推理樹各有一份三幕動畫草稿（`visual_assets`，`clinic_id` 非空，`review_status='pending'`）。
- 驗證發現：關鍵字式模板推斷很脆弱（「下顎線」誤判外科、音波被判為手術）；草稿品質只靠人工逐筆看；報告檔過時；草稿沒有寫入者紀錄（已於 88c877f 補上 `generated_at`／`generator_pid`）。

## 目標
1. 用黃金測試集鎖定 49 筆樹的預期場景 1 模板，任何推斷規則改動都會被測試抓到。
2. 每筆草稿三個場景自動渲染驗收（邊界、安全區、確定性），並產生接觸表與機器可讀報告。
3. 允許醫師以資料欄位覆寫模板，覆寫值優先於關鍵字推斷。
4. 審核清單依風險排序（外科、對照、跨診所同名優先）。

## 已確認的決策
- 不採用「讓 LLM 自由生成 HTML/GSAP」；幾何仍由已審查的前端引擎純函式渲染。
- 不採用 `whaleyxbt/claude-motion`（僅參考接觸表概念，自寫腳本實作）。
- 草稿文字不得含阿拉伯數字；不新增任何病患個資欄位（LINE、電話）。
- `clinic.db` 的 schema 遷移與資料寫入需使用者明確核准；本 phase 的計畫只在隔離副本驗證。
- 報告與接觸表輸出到 `demo/visual/out/batch_49/`（不進版控）。

## 不在範圍
- 批量重新生成草稿（需要本地 LLM 與醫師排程，另案）。
- 旁白或音效。
- 病患端 UI 變更。

## 風險
- 覆寫欄位若被誤用，可能讓錯誤模板進入審核；需在審核 CLI 顯示「覆寫來源」。
- 渲染驗收依賴 Playwright，需以既有測試夾具跳過機制處理環境缺失。
