單一來源設計（取捨說明，執行者須照此實作，不得另創他法）：
- 不新增任何標記註解區塊，直接依「欄位名稱」在 `CREATE TABLE IF NOT EXISTS faq_cache (` ... `\n);` 區塊中找「以該欄位名開頭的單行」。優點：schema 不增加第二層維護物（標記不會與欄位脫鉤）；缺點：要求欄位定義必須寫在單行內，且定義內不得含 `--` 字面值，違反時以明確 RuntimeError 拒絕（fail-closed）而不是猜測。
- ADD COLUMN 與 CREATE TABLE 語法差異：SQLite 的 ADD COLUMN 禁止 PRIMARY KEY/UNIQUE、禁止非常數預設值；NOT NULL 必須搭配非 NULL 預設值。這兩欄（`TEXT NOT NULL DEFAULT 'approved' CHECK (...)`、`TIMESTAMP`）逐字複用皆合法，因此只需「取名稱後的定義文字、去除行尾註解與單一結尾逗號」，無需轉換。若未來 schema 對這兩欄加入 ADD COLUMN 不允許的語法，SQLite 會在 ALTER 時報錯並整筆 ROLLBACK（既有交易保證），不會半遷移。
- 保留模組級常數 `ALTER_REVIEW_STATUS_SQL`、`ALTER_REVIEWED_AT_SQL`（既有測試 import 並 monkeypatch 它們），但其值改由 schema 在 import 時衍生，不再是字面字串。
- `apply_review_status_migration(db_path, schema_path=None)`：`schema_path=None` 時使用上述模組常數（正式與 conftest 路徑，維持既有 monkeypatch 回滾測試可運作）；明確給 `schema_path` 時在呼叫當下重新解析該 schema（供「改 schema → 行為改變」測試使用）。解析必須發生在 `sqlite3.connect` 之前。
</objective>
