# Phase 38: 全自動診所網站爬取與智能知識提煉引擎 (Automated Clinic Web Scraper & Distiller) - 執行計畫 (PLAN)

## 🎯 目標與交付物

建立能夠應對現代診所單頁動態應用（SPA）的自動化爬取、多頁面探索、醫療法規清洗與智能知識提煉管線，並與管理後台完整整合：
1. **Step 1 (Scraper Engine)**：`src/scraper/playwright_scraper.py` 實作 Playwright 動態網頁擷取器，支援 SPA 等待渲染。
2. **Step 2 (Crawler & Filter)**：`src/scraper/site_crawler.py` 支援同網域子頁面自動收集（Sitemap + 深度探索），並連接 `deep_mask_prices` 與 `opencc` 醫療法規清洗。
3. **Step 3 (Distillation Connect)**：`src/scraper/distill_pipeline.py` 將抓到的 Markdown 文字對接 `text_harness.py`、`faq_writer.py` 與 `db_writer.py`，自動產出 `pending` 狀態的 FAQ 與 Tree。
4. **Step 4 (Admin UI & API 整合)**：在管理後台提供非同步作業端點與前端進度回饋，一鍵完成爬取、提煉與呈現。

## 任務切分與實施步驟 (Waves)

### Wave 1: 基礎引擎層 (Step 1 & 2)

#### Task 1: Playwright 動態頁面擷取器
- **檔案**：`src/scraper/playwright_scraper.py`
- **內容**：
  - 封裝 `fetch_dynamic_page(url: str, timeout_ms: int = 15000) -> DynamicPageResult`。
  - 使用無頭 Chromium 渲染頁面，等待 `domcontentloaded` 與動態內容加載（監聽 DOM 長度或 networkidle 降級退避）。
  - 阻斷圖片、媒體、分析追蹤腳本載入以極大化擷取效能與安全性。
  - 回傳渲染後之完整 HTML、純內文文字（`inner_text`）及所有同源超連結。
- **測試**：`tests/test_playwright_scraper.py`（Mock 測試與輕量本機 HTML 渲染測試）。

#### Task 2: 同網域自動探索與醫療法規過濾器
- **檔案**：`src/scraper/site_crawler.py`
- **內容**：
  - 封裝 `crawl_clinic_site(start_url: str, max_pages: int = 8, max_depth: int = 2) -> CrawledSiteResult`。
  - 同源限制（Strict Same-Origin）：僅抓取同 Hostname 連結。
  - 優先路徑探索（Priority Queue）：加權探索包含 `service`, `treatment`, `faq`, `about`, `doctor` 之子頁面；過濾無效錨點與媒體檔案。
  - 整合 `src/ingestion/convert_chinese.py`（`opencc` 台灣正體中文）與 `deep_mask_prices()`（絕對零價格洩漏，替換為 `[請致電診所確認]`）。
- **測試**：`tests/test_site_crawler.py`。

---

### Wave 2: 智能提煉與資料入庫層 (Step 3)

#### Task 3: 知識提煉管線與雙層遞迴對接
- **檔案**：`src/scraper/distill_pipeline.py`
- **內容**：
  - 封裝 `distill_site_content(site_text: str, clinic_id: str, clinic_name: str) -> DistillationResult`。
  - 透過本地 Qwen 27B（`llama-server`）執行雙向提煉：
    1. **FAQ 提煉**：自動提煉 5~10 筆核心衛教問答，經由 `score_faq_answer_alignment()` 驗證並強制附帶就醫警訊收尾句。
    2. **PageIndex 推理樹提煉**：針對核心療程提煉為標準四段式（`pre_op`, `procedure`, `post_op_short`, `maintenance`），經由 `score_tree_distillation_alignment()` 驗證。
  - 呼叫權威寫入函式 `faq_writer.upsert_faqs()` 與 `db_writer.upsert_trees()`，狀態恆設定為 `pending`（待醫師審核）。
- **測試**：`tests/test_scraper_distill_pipeline.py`。

---

### Wave 3: 後台 API 與 UI 整合 (Step 4)

#### Task 4: 非同步爬蟲作業 API
- **檔案**：`src/api/routes/admin.py`（擴充）
- **內容**：
  - 新增 `POST /api/v1/admin/crawler/start`：接收 `clinic_id`, `url`, `targets`（FAQ / Tree），啟動背景非同步執行緒並回傳 `job_id`。
  - 新增 `GET /api/v1/admin/crawler/status/{job_id}`：查詢即時作業狀態（`crawling` ➔ `filtering` ➔ `distilling` ➔ `done` / `failed`）與提煉數量統計。
- **測試**：`tests/test_crawler_admin_api.py`。

#### Task 5: 管理後台 UI 前端整合
- **檔案**：`static/index.html`（或相關 JS 模組）
- **內容**：
  - 在「上傳與解析」頁籤的「網站解析」模式下，新增「深度自動探索與智能提煉」核取方塊。
  - 點擊「開始解析」後，以非同步模式輪詢進度條，即時呈現各階段狀態（如「已爬取 5 個子頁面...」、「正在提煉 FAQ 與推理樹...」）。
  - 完成後自動提示提煉成果，並引導切換至「常見問答」或「臨床推理樹」分頁直接進行簽核。

## 🔒 安全與合規鐵則 (Guarantees)

1. **零價格洩漏**：所有爬取之內文在進入提煉前，強制經由 `deep_mask_prices()` 進行深度遞迴遮蔽。
2. **純繁體中文原則**：所有輸出嚴格使用台灣正體中文（`opencc` `s2twp`）。
3. **無損寫入與單一權威路徑**：一律經由 `upsert_faqs` 與 `upsert_trees` 增量寫入，初始狀態恆為 `pending`，絕不擅自直接發布為 `approved`。
4. **測試隔離**：測試過程嚴格使用 `isolated_conn`，正式資料庫 `clinic.db` SHA-256 零污染。
