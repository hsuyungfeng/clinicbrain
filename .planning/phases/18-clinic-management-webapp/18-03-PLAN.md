## 2. 實作任務與端到端測試（指派 Agy 3.6 Flash）

     1. 行政人員上傳衛教文件 ➔ 成功解析並去識別化，生成 `review_status='pending'` 草稿。

     4. 醫師執行 `POST /api/v1/admin/review/faqs/{id}/approve` 核准。

2. 驗證正式庫 `clinic.db` SHA-256 恆定未變。

## 3. Claude 對抗性審查與加固（指派 Claude 5.5 Sonnet）
審查 Agy 3.6 Flash 的全套改動（API、前端與測試），重點檢查：
1. **XSS & 注入漏洞**：前端 JS 渲染是否存在未轉義的 DOM 注入風險。
2. **檔案上傳安全**：
   - 惡意檔名路徑穿越（Directory Traversal）防禦。
   - 檔案過大（超過 15MB）與非預期副檔名之阻斷有效性。
   - 暫存檔清除機制（確保例外時也能在 `finally` 區塊完全刪除）。
3. **連線安全與唯讀隔離**：
   - 確認查詢 API 使用 `PRAGMA query_only = ON;` 之唯讀連線。
   - 確認寫入 API 之交易邊界與例外 rollback。
4. **規範文檔更新**：
   - 更新 `AGENTS.md`，新增「2.17 各診所資料上傳與管理 Web App（Phase 18 新增）」章節。
5. **撰寫專屬加固測試**：`tests/test_phase18_hardening.py`。
