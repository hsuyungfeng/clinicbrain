## RED 階段（先寫會失敗的測試）

建立 `tests/test_soap_ingestion.py`，定義測試案例：
1. **五層合規攔截測試**：
   - Case A（含具體劑量處方）：醫師在對話中說「回去一天吃三顆 500mg 止痛藥」提煉出解答 $\to$ 經 `ingest_soap_records` 檢核被拒絕，錯誤代碼 `dosage_prescription`，未寫入資料庫。
   - Case B（含價格）：提到「雷射一堂 3000 元」 $\to$ 被價格檢測拒絕，未寫入資料庫。
   - Case C（general 缺少就醫警訊）：通用衛教解答僅提到「多喝水休息」 $\to$ 因缺少警訊段落被拒絕。
   - Case D（合規項目）：合規衛教問答（無價格、無簡體、無保證療效、無具體劑量、含警訊指引） $\to$ 順利寫入。
2. **審核狀態與可見性防禦測試**：
   - 驗證寫入後的記錄其 `source_type == 'clinical_soap'`，且 `review_status == 'pending'`。
   - 透過 `visible_faq_sql` 查詢，該筆記錄不可見；執行查詢端點時不會短路亦不會回傳此記錄。
3. **Fail-Closed 防禦測試**：
   - 若資料庫尚未包含 `review_status` 欄位，嘗試寫入 `clinical_soap` 會引發 `RuntimeError`，阻斷無審核欄位下的寫入。

RED 驗證：`python3 -m pytest tests/test_soap_ingestion.py -x 2>&1 | tail -5` — 預期 `FAILED`。

  ```python
  def visible_faq_sql(conn: sqlite3.Connection) -> str:
      """產生供 faq_cache 查詢 WHERE 子句共用的可見性 SQL 片段。"""
      if has_review_status(conn):
          return "(source_type NOT IN ('llm_generated', 'clinical_soap') OR review_status = 'approved')"

  ```
